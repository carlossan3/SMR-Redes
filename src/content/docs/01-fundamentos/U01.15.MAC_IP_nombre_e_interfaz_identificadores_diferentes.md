# U01.15 — MAC, IP, nombre e interfaz: identificadores diferentes

## 🎯 Qué vas a conseguir

Al terminar este apartado deberías ser capaz de:

- distinguir **interfaz de red**, **dirección MAC**, **dirección IP** y **hostname**;
- explicar qué identifica cada elemento y por qué no son equivalentes;
- comprender que un mismo equipo puede tener **varias interfaces**;
- relacionar una MAC con una interfaz de red;
- entender que una IP es un identificador **lógico** asociado a una interfaz en una red;
- reconocer que el hostname es un **nombre del equipo**, no una sustitución automática de la MAC o la IP;
- interpretar una salida muy básica de Debian sin modificar la configuración.

> 📌 **CE principal:** RA1.c — reconocimiento de hosts, NIC e interfaces y otros elementos. Refuerza RA1.a al relacionar identificadores con la comunicación.

## 📬 Idea clave

> **Un ordenador no tiene “una única dirección”: puede tener varias interfaces y cada concepto —interfaz, MAC, IP y hostname— responde a una pregunta distinta.**

Piensa en una persona:

```text
NOMBRE       → cómo la llamamos
DNI          → identidad
DOMICILIO    → dónde está ahora
PUERTA       → por dónde entra o sale
```

En una red, la analogía puede ayudarte:

```text
HOSTNAME  → nombre del equipo
MAC       → identificador de una interfaz en el enlace
IP        → dirección lógica de una interfaz en una red
INTERFAZ  → punto de conexión del equipo con una red
```

La analogía no es perfecta, pero sirve para no mezclar conceptos.

---

## 🔌 Interfaz de red — Por dónde se conecta el equipo

Una **interfaz de red** es el punto mediante el que un dispositivo se conecta a una red.

Puede ser:

- una tarjeta Ethernet;
- una interfaz Wi-Fi;
- una interfaz virtual;
- otras interfaces según el equipo.

Un portátil puede tener, por ejemplo:

```text
PORTÁTIL
├── interfaz Ethernet
└── interfaz Wi-Fi
```

Por tanto:

> **Un equipo puede tener más de una interfaz de red.**

En Debian verás nombres como:

```text
enp0s3
wlp2s0
lo
```

Los nombres exactos dependen del equipo y de su configuración.

No necesitas memorizarlos. Debes saber **reconocer que son interfaces diferentes**.

---

## 🖲️ Dirección MAC — Identificador de enlace

La **dirección MAC** (*Media Access Control*) es un identificador asociado a una interfaz de red y utilizado en la comunicación de **capa 2**.

Suele representarse en hexadecimal:

```text
52:54:00:12:34:56
```

Características importantes para este nivel:

- tiene **48 bits** en Ethernet tradicional;
- se representa normalmente como 6 grupos hexadecimales;
- está asociada a una **interfaz**;
- se utiliza en la comunicación dentro del enlace local;
- puede existir más de una MAC en un equipo si tiene varias interfaces.

> 📌 Una simplificación habitual dice que la MAC es “la matrícula del equipo”. Es mejor decir **la matrícula de una interfaz de red**, porque un equipo puede tener varias.

### Importante

En cursos introductorios se presenta como un identificador asignado al hardware. En la práctica, el software puede modificar o aleatorizar la MAC en algunos sistemas y situaciones.

Para esta unidad quédate con la función:

> **La MAC identifica una interfaz en la comunicación de enlace local.**

---

## 🌐 Dirección IP — Dirección lógica

La **dirección IP** es un identificador lógico utilizado para situar una interfaz dentro de una red IP.

Ejemplo IPv4:

```text
192.168.1.25
```

A diferencia de la MAC:

- puede cambiar al conectarte a otra red;
- depende de la configuración de red;
- se utiliza en la capa de **Red**;
- una interfaz puede tener más de una dirección IP;
- diferentes interfaces del mismo equipo pueden tener IP distintas.

> 💡 Hoy solo distinguimos el concepto. Las máscaras, los prefijos, el cálculo de redes y el subnetting se estudiarán más adelante.

---

## 🏷️ Hostname — El nombre del equipo

El **hostname** es el nombre asignado a un equipo dentro del sistema.

Ejemplos:

```text
pc-aula-12
servidor-biblioteca
debian-carlos
```

Sirve para que las personas y los sistemas puedan referirse a un equipo mediante un nombre legible.

Pero:

> **hostname ≠ IP ≠ MAC**

Un hostname puede mantenerse aunque cambie la IP.

Y una misma máquina puede tener varias interfaces y, por tanto, varias direcciones, aunque conserve un único nombre de sistema.

---

## ⚖️ Los cuatro conceptos frente a frente

| Concepto | Pregunta que responde | Ejemplo |
|---|---|---|
| **Interfaz** | ¿Por qué punto se conecta el equipo? | `enp0s3`, Wi-Fi |
| **MAC** | ¿Qué identificador tiene esa interfaz en el enlace? | `52:54:00:12:34:56` |
| **IP** | ¿Qué dirección lógica tiene esa interfaz en esta red? | `192.168.1.25` |
| **Hostname** | ¿Cómo se llama el equipo? | `pc-aula-12` |

## 🧠 Un mismo equipo, varios identificadores

Imagina este portátil:

```text
Hostname: alumno-07

Ethernet:
  interfaz: enp0s3
  MAC:      52:54:00:AA:10:01
  IP:       192.168.1.27

Wi-Fi:
  interfaz: wlp2s0
  MAC:      8C:85:90:BB:20:02
  IP:       192.168.1.88
```

¿Qué observas?

1. El equipo tiene **un hostname**.
2. Tiene **dos interfaces**.
3. Cada interfaz posee su propia **MAC**.
4. Cada interfaz puede tener su propia **IP**.

Esta es la razón por la que decir «la MAC del ordenador» puede ser demasiado impreciso.

Una pregunta mejor sería:

> «¿Qué MAC tiene la interfaz Ethernet?»

---

## 🔁 Qué puede cambiar y qué puede mantenerse

| Elemento | ¿Puede cambiar? | Comentario |
|---|---|---|
| **Hostname** | Sí | El administrador puede modificarlo |
| **Interfaz** | Sí | Se pueden añadir, quitar o crear interfaces |
| **MAC** | Puede cambiarse o aleatorizarse | Está asociada a la interfaz y suele venir asignada por hardware |
| **IP** | Sí, con frecuencia | Cambia según la red o configuración |

> ⚠️ Evita la idea absoluta «la MAC jamás cambia». Como introducción histórica es útil, pero técnicamente el software puede modificarla en determinadas situaciones.

## 🐧 Primer vistazo en Debian

Sin cambiar nada, puedes observar estos datos con comandos básicos.

### Ver el nombre del equipo

```bash
hostname
```

### Ver interfaces y direcciones MAC

```bash
ip link
```

### Ver direcciones IP de las interfaces

```bash
ip address
```

También puede abreviarse:

```bash
ip addr
```

> 📌 **Observar no es configurar.** En esta sesión solo leeremos información del sistema.

---

## 🔍 Cómo leer una salida sin asustarse

Una salida de `ip link` puede contener algo parecido a:

```text
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
    link/ether 52:54:00:12:34:56 ...
```

Qué nos interesa ahora:

```text
enp0s3                → nombre de la interfaz
52:54:00:12:34:56     → dirección MAC
```

Una salida de `ip address` puede añadir:

```text
inet 192.168.1.25/24
```

En esta sesión:

```text
192.168.1.25          → dirección IPv4
/24                   → prefijo de red, que estudiarás con calma más adelante
```

No necesitas calcular nada todavía.

## 🤬 CONRAD VS EL MUNDO: «Mi PC tiene la IP enp0s3»

> **CONRAD:** —He encontrado mi IP: `enp0s3`.
>
> —Eso es el nombre de una interfaz.
>
> **CONRAD:** —Entonces mi MAC es `pc-aula-04`.
>
> —Eso parece el hostname.
>
> **CONRAD:** —¿Y `192.168.1.28`?
>
> —Eso sí tiene aspecto de una IPv4.
>
> **CONRAD:** —¿Por qué hay tantas etiquetas?
>
> —Porque describen cosas distintas.
>
> **CONRAD:** —Propongo llamar a todo «la cosa de red».
>
> —Propuesta rechazada.

</details>

### Razona

Un portátil tiene Ethernet y Wi-Fi.

¿Puede tener dos direcciones MAC?

<details>
<summary>🔄 Respuesta</summary>

Sí. Cada interfaz de red puede tener su propia **dirección MAC**, por lo que un portátil con Ethernet y Wi-Fi puede presentar al menos una MAC para cada una.

</details>

---

## ✅ Resumen en 3 frases

1. Un equipo puede tener varias **interfaces**, y cada una puede disponer de su propia MAC y dirección IP.
2. La **MAC** se utiliza como identificador de enlace; la **IP** es una dirección lógica; el **hostname** es el nombre del equipo.
3. En Debian puedes observar estos datos con `hostname`, `ip link` e `ip address` sin modificar la configuración.
